Reference Blueprint

Twilio LiveKit Flex Handoff

A production-shaped pattern for giving a LiveKit voice agent a clean escape hatch to a human agent in Twilio Flex, without losing the caller or the context gathered by the AI.

View Call Flow Implementation Map
Pattern: SIP to LiveKit, parent call update to Flex Voice + TaskRouter

What This Blueprint Solves

AI containment with a safe human handoff

The integration lets a LiveKit voice agent handle the first part of an inbound support call. When the agent cannot resolve the issue, it calls a tool that updates the original Twilio call into a Flex TaskRouter workflow. The caller stays on the same live call while the human agent receives structured handoff context.

Twilio Voice

Owns the live caller leg

Twilio receives the inbound phone call and keeps the parent call active while a SIP child leg connects to LiveKit.

LiveKit

Runs the AI voice agent

LiveKit receives the SIP media, starts the configured agent, and exposes SIP headers as participant attributes.

Flex

Receives the escalation

TaskRouter receives a voice task containing the handoff summary, intent, caller details, and parent call SID.

Runtime Flow

How the call moves from AI to human

The key design choice is to update the original inbound Twilio call resource during escalation. The LiveKit SIP leg is only the media bridge to the AI agent; it is not the call leg that should be enqueued into Flex.

Caller reaches Twilio

The Twilio number invokes the public /voice Function for the inbound call.

Twilio dials LiveKit over SIP

/voice returns <Dial><Sip> with authentication and custom SIP headers, including X-Parent-CallSid.

LiveKit starts the configured agent

The inbound SIP trunk maps X-Parent-CallSid to parentCallSid, and the dispatch rule sends the call to the target LiveKit agent.

The agent requests handoff

The LiveKit tool posts parentCallSid, intent, and summary to the Twilio /escalate Function.

Twilio updates the parent call

/escalate replaces the parent call's TwiML with <Enqueue workflowSid="WW..."> and includes the handoff data as TaskRouter attributes.

Flex receives the voice task

A human agent accepts the task in Flex and receives the live caller plus the context collected by the AI agent.

Parent Call Update

The small detail that makes the handoff work

Twilio creates a parent call leg for the original inbound caller and a child SIP leg for LiveKit. The handoff must update the parent leg.

Header passed to LiveKit

const parentCallSid = event.CallSid;
const sipParams = new URLSearchParams({
  "X-Parent-CallSid": parentCallSid,
  "X-Handoff-Id": event.CallSid,
});

Call update during escalation

await client.calls(parentCallSid).update({
  twiml: enqueueTwiml.toString(),
});

Avoid updating the SIP child leg exposed inside LiveKit. That leg represents the AI media bridge. The parent call is the live caller that needs to be moved into the Flex queue.

Task Attributes

Context passed into Flex

The escalation Function serializes handoff context into the TaskRouter task. Flex can read these attributes from the active reservation or task. 

{
  "direction": "inbound",
  "channelType": "voice",
  "reason": "ai_escalation",
  "name": "LiveKit AI escalation",
  "parentCallSid": "CA...",
  "handoffId": "CA...",
  "intent": "account_access",
  "summary": "Caller tried a new sign-in code and still needs help.",
  "description": "Caller tried a new sign-in code and still needs help."
}

Setup Checklist

Build it in four moves

1. Deploy Twilio Functions

Deploy /voice and /escalate with the Flex workflow SID, LiveKit SIP host, SIP credentials, and shared handoff token.

2. Create LiveKit SIP resources

Create the inbound trunk from the template, then bind the SIP dispatch rule to the returned ST... trunk ID.

3. Configure the Twilio number

Point the Twilio number's incoming voice webhook at the public /voice Function URL.

4. Add the LiveKit tool

Add transfer_to_flex to the LiveKit agent and set HANDOFF_SERVICE_URL plus HANDOFF_TOKEN in the agent environment.

Adaptation

Using the pattern without Flex

Flex is the concrete target in this blueprint, but the core pattern is broader. If your human-agent stack uses TaskRouter, enqueue the parent call and pass context as task attributes. If it does not, you can still route the live call with TwiML such as <Dial>, but you will need a separate context channel for the receiving desktop or agent system.
